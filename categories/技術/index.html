ESP32-C6 + Fly.io 裝置管理站實作筆記：註冊碼與自動換 Key

這陣子手邊的 ESP32-C6 要做一件聽起來很簡單的事：把紅外線發射的訊號、設備開關機的紀錄，通通丟到雲端存起來，然後打開網頁，一眼看出「這塊板子現在是死是活、設備有沒有在跑」。

說實話，我一開始的想法是：不就一支 API 嗎？結果越做越發現，真正麻煩的從來不是「收資料」，而是 怎麼讓一堆板子安安全全地證明自己是誰。Key 要怎麼塞進板子？外洩了怎麼辦？放在現場沒人管的板子，Key 能不能自己換？

這篇就是把整個過程記下來：架構怎麼選、Key 的生命週期怎麼設計、部署到 Fly.io 的細節，以及我（和 Claude Code）一路踩到的坑。先講在前面：伺服器端已經上線、也測過了，但 ESP32 韌體我只寫了範例，還沒有真的編譯、燒進板子。後面會老實交代。

2010 年老筆電復活！OpenClaw LINE 頻道配對實戰與解密

OpenClaw 部署最佳實踐：從 3.1 邁向 4.2 的老戰友指南

前言

最近把身邊幾台 OpenClaw 從穩定（但已經快變遺產？）的 2026.3.1 升級到 2026.4.2。本來以為是個 pnpm install 就能解決的小事，沒想到這中間的配置變更跟環境限制，還是讓我小坐了一下牢。

特別是我的主力戰友——那台 MacBook Air 2010 款。雖然它年紀比很多讀者的貓還大，但我已經把它加爆到 16GB RAM 了！老兵不死，只是需要在升級時多給它一點關愛。寫這篇主要就是想把這些踩坑經驗留下來，給同樣擁抱老設備或追求極致省錢（守護荷包）的大家一個參考。

或是說，先把信用卡準備好就好(?)。
